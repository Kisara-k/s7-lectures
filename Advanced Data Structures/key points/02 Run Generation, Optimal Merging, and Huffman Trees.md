## 2. Run Generation, Optimal Merging, and Huffman Trees

## Key Points

#### 1. 🏃 Run Generation
- Using 2 input and 2 output buffers with a min loser tree improves run generation efficiency.
- The minimum run size generated by a loser tree with k external nodes is at least k.
- Average run size using a loser tree is approximately 2k.
- Total internal processing time for run generation using a loser tree is $O(n \log k)$.

#### 2. 🔀 Weighted External Path Length (WEPL)
- WEPL is calculated as the sum of (weight of external node) × (distance from root).
- Minimizing WEPL minimizes total merging or decoding cost.
- WEPL applies to merging runs of different lengths and message coding.

#### 3. 📡 Message Coding and Decoding
- Messages are assigned codes based on their frequencies to minimize transmission and decoding cost.
- Decoding cost equals transmission cost and equals the WEPL of the code tree.
- Every binary tree with n external nodes defines a prefix code set for n messages.

#### 4. 🗜️ Lossless Data Compression
- Variable-length prefix codes reduce total bits needed compared to fixed-length codes.
- Compression ratio improves when the decode tree has minimum WEPL.
- Prefix property: no code is a prefix of another, ensuring unambiguous decoding.

#### 5. 🌲 Huffman Trees
- Huffman trees are binary trees with minimum WEPL.
- Huffman trees are constructed using a greedy algorithm combining two smallest-weight trees repeatedly.
- Using a min-heap, Huffman tree construction runs in $O(n \log n)$ time.

#### 6. 🌳 Higher-Order Trees
- Greedy algorithm for minimum WEPL does not always work for k-ary trees (k > 2).
- To fix this, add q zero-weight runs so that $(r + q - 1) \mod (k - 1) = 0$, where r is the initial number of runs.
- This ensures all internal nodes have exactly k children.

#### 7. 💾 Buffer Management in k-Way Merging
- Exactly 2 output buffers and at least $k+1$ input buffers are needed for merging k runs.
- Input buffers are allocated dynamically based on which run will exhaust first, determined by the smallest last key read.
- The kWayMerge method merges input buffers into the active output buffer until full or end-of-run key is merged.
