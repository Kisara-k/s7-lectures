## 7 IPv6

## Study Notes

### 1. 🌐 Introduction to IPv6: Why We Need It

IPv6, or Internet Protocol version 6, is the latest version of the Internet Protocol designed to replace IPv4, which has been the backbone of the internet for decades. The main reason IPv6 was developed is because IPv4’s address space is running out. IPv4 uses 32-bit addresses, which limits the total number of unique IP addresses to about 4.3 billion. With the explosive growth of internet-connected devices worldwide, especially outside the Americas, this number is no longer sufficient.

IPv6 was designed with several important goals in mind:

- **More address space:** IPv6 uses 128-bit addresses, vastly increasing the number of available IP addresses.
- **Smaller global routing tables:** To keep the internet scalable and efficient.
- **Removal of unused or problematic IPv4 features:** Simplifying the protocol.
- **Built-in security:** IPv6 includes native support for encryption and authentication.
- **Improved multicast support:** For efficient data distribution to multiple destinations.

Historically, before IPv6 was finalized, there were competing proposals with different address lengths (64-bit, 128-bit). The current 128-bit scheme was agreed upon in 1994 at the IETF meeting in Toronto.


### 2. 🏠 Private Address Space and NAT: The IPv4 Stopgap

Before IPv6, the shortage of IPv4 addresses led to the widespread use of **private address spaces** (defined in RFC1918). These are IP ranges reserved for internal use within organizations and are not routable on the public internet. To connect these private networks to the internet, **Network Address Translation (NAT)** was developed.

NAT allows multiple devices on a private network to share a single public IP address. While this helped extend the life of IPv4, it introduced some problems:

- **Loss of transparency:** NAT hides the real IP addresses of devices, complicating direct communication.
- **Bifurcation of the Internet:** Some parts of the internet became "application rich" (fully accessible) while others became "application poor" (limited by NAT).
- **Network management challenges:** Diagnosing and managing networks became harder because NAT obscures the true source and destination of traffic.

IPv6 aims to eliminate the need for NAT by providing enough addresses for every device to have a unique public IP.


### 3. 🆔 IPv6 Addressing: Structure and Types

#### Address Length and Format

IPv6 addresses are **128 bits long**, compared to 32 bits in IPv4. Typically, an IPv6 address is split into two 64-bit parts:

- The **network prefix** (first 64 bits), assigned by the network administrator.
- The **interface identifier** (last 64 bits), often derived from the device’s MAC address.

Addresses are written as eight groups of four hexadecimal digits, separated by colons. For example:

```
3ffe:3700:0200:00ff:0000:0000:0000:0001
```

To simplify, leading zeros in each group can be omitted, and one contiguous sequence of zero groups can be replaced by a double colon `::`. For example:

```
3ffe:3700:200:ff::1
```

#### Types of IPv6 Addresses

IPv6 supports several types of addresses, similar to IPv4 but with some differences:

- **Unicast:** Delivered to a single interface. This is the most common type.
- **Multicast:** Delivered to all interfaces that have the multicast address.
- **Anycast:** Delivered to the nearest interface (in terms of routing distance) among a group of interfaces sharing the same address.

**Note:** IPv6 does **not** have broadcast addresses. Instead, multicast replaces broadcast functionality, which is more efficient.


### 4. 🔍 Special IPv6 Unicast Addresses

IPv6 defines several special unicast addresses with specific purposes:

- **Unspecified address (`::`):** All zeros. Used as a source address during initialization when the device does not yet have an IP.
- **Loopback address (`::1`):** Equivalent to IPv4’s 127.0.0.1, used for sending packets to the same device.
- **Link-local addresses:** Begin with `FE80::/10`. These are unique only within a local subnet and are automatically configured. Routers do not forward packets with link-local addresses.
- **Site-local addresses:** Begin with `FEC0::/10`. Intended for use within a site or organization, but their use is discouraged and considered deprecated.
- **IPv4-mapped addresses:** Used by dual-stack devices to represent IPv4 addresses within IPv6, formatted as `::FFFF:a.b.c.d`.
- **IPv4-compatible addresses:** Used for automatic tunneling between IPv6 hosts over IPv4 networks, formatted as `::a.b.c.d`.


### 5. 🆔 Interface Identifiers: Linking IPv6 to Hardware

The last 64 bits of an IPv6 address often come from the device’s hardware MAC address, using a method called **EUI-64**. This ensures that the interface identifier is unique on the local network.

The process to convert a 48-bit MAC address to a 64-bit interface identifier involves:

- Splitting the MAC address into two parts.
- Inserting the fixed 16-bit value `FFFE` in the middle.
- Flipping the 7th bit of the first byte (called the universal/local bit).

For example, a MAC address `00-02-2D-02-82-34` becomes `0202:2dff:fe02:8234` in EUI-64 format.

#### Privacy Concerns and Privacy Addresses

Because the interface identifier can reveal the device’s MAC address, privacy concerns arose. To address this, **privacy addresses** were introduced, which use random 64-bit numbers instead of the MAC-based identifier. These addresses can change over time or per connection to enhance user privacy.


### 6. 🔄 IPv6 Autoconfiguration: Plug and Play Networking

One of IPv6’s strengths is its ability to configure itself automatically without manual setup or DHCP (though DHCPv6 exists for more control).

When a device connects to a network:

1. It assigns itself a **link-local address** using the `FE80::/10` prefix and its interface identifier.
2. It listens for **Router Advertisement (RA)** messages from routers on the network.
3. Routers send RA messages containing the network prefix (usually a `/64`).
4. The device combines the prefix with its interface identifier to form a globally routable IPv6 address.
5. If no router responds, the device continues to use only its link-local address.

This process allows devices to join networks quickly and easily, supporting plug-and-play connectivity.


### 7. 📡 Multiple Addresses and Address Selection

IPv6 assumes that each interface will have multiple addresses simultaneously, such as:

- Link-local address
- One or more global unicast addresses (EUI-64 based or privacy)
- Possibly site-local addresses

This flexibility supports multi-homing (connecting to multiple networks) and privacy.

However, having multiple addresses can cause problems:

- Applications or hosts may choose the "wrong" address for outgoing connections, potentially breaking routing policies or connectivity.
- Address selection rules exist to guide this choice, but they are complex and sometimes controversial.


### 8. 📦 IPv6 Packet Structure: Simplified and Efficient

IPv6 packets have a simplified header compared to IPv4, designed to speed up processing by routers:

- **Version (4 bits):** Identifies IPv6.
- **Traffic Class (8 bits):** Similar to IPv4’s Type of Service, used for QoS.
- **Flow Label (20 bits):** New field to identify packet flows for special handling.
- **Payload Length (16 bits):** Length of the data following the header.
- **Next Header (8 bits):** Indicates the type of the next header (e.g., TCP, UDP, or extension headers).
- **Hop Limit (8 bits):** Same as IPv4’s TTL, limits packet lifetime.
- **Source and Destination Addresses (128 bits each):** The sender and receiver IPs.

#### Header Simplifications

- Fixed header length (no variable-length options).
- No header checksum (relies on checksums at other layers like TCP/UDP).
- No fragmentation by routers; hosts must perform Path MTU Discovery.
- Extension headers allow optional information without complicating the main header.

#### Extension Headers

IPv6 uses extension headers to add optional features:

- Hop-by-Hop Options
- Routing Header
- Fragmentation Header
- Destination Options
- Authentication Header (for security)
- Encrypted Security Payload Header (for encryption)


### 9. 🔀 Transition to IPv6: Coexistence and Tunneling

IPv6 deployment is gradual. Initially, IPv6 networks exist as "islands" within the IPv4 internet. To connect these islands, **tunneling** is used:

- IPv6 packets are encapsulated inside IPv4 packets.
- This allows IPv6 traffic to traverse IPv4 infrastructure.
- Tunnels add overhead and can cause MTU issues but enable incremental deployment.

#### Application Layer Gateways (ALGs)

Some applications embed IP addresses in their payloads (e.g., FTP, SIP). ALGs translate these addresses to work across IPv4/IPv6 boundaries, similar to how NAT devices operate.


### 10. 🌍 DNS and IPv6: Naming Challenges

DNS, the system that translates domain names to IP addresses, must support IPv6:

- **AAAA records:** New DNS record type for IPv6 addresses (type 28).
- Dual-stack hosts must decide whether to query A (IPv4) or AAAA (IPv6) records.
- Namespace fragmentation can occur if IPv4-only and IPv6-only DNS servers are not synchronized.
- Mail exchange (MX) records must handle IPv6 addresses to allow email delivery between IPv4 and IPv6 users.


### 11. ⚙️ Implementing IPv6: Practical Considerations

Deploying IPv6 requires:

- Upgrading software on routers, switches, and hosts.
- Updating firewalls and security policies to handle new protocols and headers.
- Ensuring ICMPv6 is enabled and rate-limited (important for network functions like Neighbor Discovery).
- Supporting new features like extension headers and privacy addresses.

Most modern operating systems and common network tools (Apache, Sendmail, Mozilla, Bind, FTP, ping, traceroute) already support IPv6.


### Summary

IPv6 is a major upgrade to the Internet Protocol designed to solve the address exhaustion problem of IPv4 while improving security, routing efficiency, and network management. It introduces a much larger address space, new address types, simplified packet headers, and automatic configuration features. Transitioning to IPv6 involves coexistence with IPv4 through tunneling and dual-stack operation, along with updates to DNS and application protocols.

Understanding IPv6 is essential for modern networking, as the internet continues to grow and evolve.
